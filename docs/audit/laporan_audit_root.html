Penyimpanan Berkas Dokumen Sensitif ASN pada Public Disk Web Server (Pelanggaran UU PDP & BSSN)
app/Domain/Pendaftaran/Actions/StorePendaftaranAction.php:56 & app/Http/Controllers/PengajuanKunjunganController.php:63
▼
Deskripsi & Dampak

Pada penambahan fitur V6, modul pendaftaran mendukung unggah berkas bukti kepemilikan TTE aktif sebelumnya (file_bukti_tte) dan modul kunjungan layanan mendukung unggah surat dinas permohonan SKPD (file_surat_permohonan). Berkas-berkas tersebut disimpan secara langsung ke dalam disk 'public' (storage/app/public/bukti_tte dan storage/app/public/kunjungan).

Dampak Kritis: Berkas sertifikat elektronik memuat data identitas privat aparatur negara (NIK, NIP, nama lengkap, jabatan, unit kerja, serta tanda tangan elektronik BSrE). Begitu symlink web server publik (public/storage) aktif, siapa saja di internet publik dapat mengakses dan mengunduh berkas fisik ini secara langsung tanpa autentikasi, tanpa VPN gateway, dan tanpa kontrol akses. Hal ini merupakan pelanggaran berat terhadap UU No. 27 Tahun 2022 tentang Pelindungan Data Pribadi (UU PDP) serta regulasi keamanan siber persandian negara.

Rekomendasi Tata Cara Perbaikan
  1. Alihkan penyimpanan berkas bukti TTE dan surat kunjungan dari disk 'public' ke disk privat 'local' (disimpan di storage/app/private/ atau storage/app/secure_docs/).
  2. Pastikan direktori penyimpanan privat berada di luar web-root Nginx dan tidak terhubung ke symlink publik.
  3. Sediakan rute controller administratif terproteksi (misal: /admin/verifikasi/{id}/download-bukti) yang dilindungi oleh middleware ['vpn.gateway', 'auth'] serta Policy authorization sebelum melayani streaming berkas melalui Storage::disk('local')->download() atau response()->file().

Penggunaan Metode getClientOriginalExtension() pada Unggah Berkas Publik (Unsafe File Extension)
app/Http/Controllers/PengajuanKunjunganController.php:62
▼
Deskripsi & Dampak

Pada penanganan berkas surat permohonan kunjungan layanan, penamaan file pada disk disusun menggunakan $file->getClientOriginalExtension() yang mempercayai header HTTP kiriman klien browser secara mentah.

Dampak Kritis: Header klien dapat dimanipulasi dengan mudah oleh penyerang menggunakan proxy tools (seperti Burp Suite) untuk menyuntikkan ekstensi berbahaya atau ekstensi ganda (misal: permohonan.php%00.pdf atau malicious.phtml). Hal ini membuka celah eksekusi skrip tidak sah (Remote Code Execution) jika terdapat celah konfigurasi pada web server.

Rekomendasi Tata Cara Perbaikan
  1. Ganti getClientOriginalExtension() dengan metode bawaan $file->extension() yang mendeteksi ekstensi berdasarkan MIME-type inspeksi byte riil berkas (*magic bytes*) oleh Symfony.
  2. Gunakan $file->hashName() untuk menghasilkan string acak aman SHA-1 murni tanpa mempertahankan nama asli dari klien.

Deskripsi & Dampak

Aplikasi dikonfigurasi menggunakan driver antrian Redis asynchronous (QUEUE_CONNECTION=redis). Job kritis seperti UpdateSertifikatStatusJob dan audit log didorong ke dalam antrian Redis. Namun di dalam docker-compose.yml, hanya ada container tte_app (yang menjalankan daemon PHP-FPM untuk melayani HTTP request).   1. Tambahkan service queue khusus pada docker-compose.yml menggunakan image runtime PHP yang sama.
  2. Jalankan perintah php artisan queue:work redis --queue=default,audit-logs --sleep=3 --tries=3 --timeout=90 di bawah supervisi Docker restart policy.

Deskripsi & Dampak

Pada berkas docker/php/php.ini, direktif session.cookie_secure ditetapkan bernilai 0.

Dampak: Walaupun Laravel mengatur cookie melalui config/session.php, konfigurasi dasar runtime PHP seharusnya menerapkan prinsip *Defense in Depth* dengan mewajibkan flag secure = 1 untuk mencegah kebocoran cookie pada kanal yang tidak terenkripsi TLS/HTTPS.

Rekomendasi Tata Cara Perbaikan
  1. Ubah nilai session.cookie_secure = 1 pada docker/php/php.ini.
